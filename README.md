# دورهمی | Family Circle
A lightweight, RTL, invite-only family chat and private photo gallery.

## Architecture
- Static HTML/CSS/JavaScript front end (GitHub Pages / Vercel compatible).
- Supabase Auth + PostgreSQL (RLS) + Realtime + private Storage.
- Zero family content in the Git repository or browser demo.
- Deployment is intentionally locked to **visual demo only** without a configured Supabase project.

## Secure setup
1. Create a separate Supabase project (do not reuse production MalGuard infrastructure).
2. Leave email confirmation ON. Run sql/schema.sql in Supabase SQL Editor **once**.
3. Add your email-verified account to family_members using the commented bootstrap SQL in the schema. Only do this after checking the auth.users email.
4. Edit config.js with Supabase project URL and the *public* anon/publishable key only. Never use service_role keys in the browser or GitHub.
5. Publish the static files. New users can register, confirm email, enter a one-time code generated by an admin, then access chats.
6. Verify access denial: unauthenticated user; signed-in nonmember; member reading unrelated conversation; reused code; wrong email; expired code; unauthorized photo URL. All must be denied.

## Caveats
- True background web-push notifications require a separate push service and are not in v1. Realtime notifications work while the site is open.
- Browser application code is publicly viewable on any static host. Private data remains in Supabase protected with RLS, not in static files.
- Public .vercel.app hosting is not a private access gate. Access protection is enforced by Auth + RLS.
- Supabase free plan limits and inactivity policies apply.
- Do not use real family data until backend security and integration tests have been completed.
- SQL schema uses CREATE POLICY statements; meant for fresh installation, not repeat execution without a migration.
